# Finish 2 — Phase 1 Implementation Plan (foundations)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The three P1 foundations from the Finish 2 design: graph undo/redo (D4), multiple named Output operators with per-output export and selected-output preview (D1), and the Scale operator with per-node resolution propagation in BOTH renderers (D2).

**Architecture:** No schema changes — everything lives in graph JSON (new node kind `scale`, output `name` param) and component state (undo history). The engine rework splits "render the chain" from "place onto a page": the chain runs at per-node resolutions (sources native, Scale changes it, everything else inherits its first input), placement happens per output node. Parity moves from per-effect graphs to named graph CASES stored as JSON consumed by both golden writer and JS harness.

**Tech Stack:** unchanged (Tauri v2, React 19, TS, @xyflow/react, WebGL2; Rust wgpu/naga/image).

**Spec:** [docs/superpowers/specs/2026-09-08-finish-2-design.md](../specs/2026-09-08-finish-2-design.md) (D1, D2, D4)

## Global Constraints

- House rules as v1: design tokens only, ALL UI text via `useT()` with EN/FR parity (accent-free FR), lint zero findings, gates green per commit (`npx tsc --noEmit && npm test && npm run lint`, `cargo test` in src-tauri).
- Shader/portability discipline: integer hashes only, no `fract(sin(...))`; frag normalization contract unchanged.
- TS↔Rust mirrors must stay in lockstep: resolution propagation, output-settings parsing, placement math. The parity cases (Task 4) are the net — every mirror change regenerates and re-verifies goldens.
- Graph JSON stays v1 (`v: 1`): new node kind and params are additive; `parseGraph` must keep accepting every graph the shipped app ever wrote.
- The existing global Cmd+Z is claimed by `useUndoStore` (App.tsx, document bubble listener). Finish's graph undo preempts it with a CAPTURE-phase document listener active only while FinishTab is mounted, and never fires when focus is in INPUT/TEXTAREA/SELECT/contenteditable (native/text undo wins).
- `npm run parity` is a pre-release gate, not part of `npm test` ([RELEASING.md](../../../RELEASING.md)).

### Task 1: Graph undo/redo (D4)

**Files:**
- Create: `src/lib/graphHistory.ts`, `src/lib/__tests__/graphHistory.test.ts`
- Modify: `src/components/finish/FinishTab.tsx`
- Test: extend `src/components/finish/__tests__/finish.test.tsx`

**Interfaces:**
- `graphHistory.ts` (pure, no React): `createHistory(limit = 100)` returning `{ push(json: string, now: number): void; undo(): string | null; redo(): string | null; canUndo(): boolean; canRedo(): boolean }`. Push coalesces: replaces the top entry instead of stacking when called < 400ms after the previous push (param-drag streams collapse to one entry). `undo()` returns the PREVIOUS state and moves the current one to the redo stack; any fresh `push` clears redo.
- FinishTab: history seeded with the initial graph; every `setGraph` path routes through one `commitGraph(next)` that pushes `serializeGraph(next)`; keydown handler (document, `capture: true`, mounted-only) on Cmd+Z / Cmd+Shift+Z calls `e.preventDefault(); e.stopPropagation()` and applies `parseGraph` of the popped state. Focus guard per Global Constraints.
- Undo restores selection sanity: if the selected node no longer exists, clear selection.

### Task 3: Scale operator + per-node resolution (D2)

**Files:**
- Modify: `src/lib/finishGraph.ts` (kind `"scale"`, `nodeResolutions`), `src/lib/glExecutor.ts`, `src/components/finish/NodeCanvas.tsx`, `src/components/finish/ParamsPanel.tsx`, `src/__tests__/setup.ts` (only if the xyflow mock needs the new type — it renders by nodeTypes map, should not)
- Modify (Rust): `src-tauri/src/render/engine.rs`, `src-tauri/src/render/mod.rs`
- Test: `src/lib/__tests__/finishGraph.test.ts`, `src-tauri/tests/render.rs`

**Interfaces:**
- Model: `kind: "scale"` node, params `{ factor: number (0.05–4, default 0.5), width?: number, height?: number, filter: "smooth" | "pixel" }` — absolute width/height (px, 16–16384) override factor when BOTH set. `parseGraph` accepts it; `executionOrder`/`wouldCycle` untouched (kind-agnostic).
- `nodeResolutions(g, sourceDims: Map<id, {w,h}>, cap: number): Map<id, {w,h}>` — pure TS: source = native clamped to cap (aspect kept); scale = input res × factor or absolute (clamped 1..cap); effect/output-thumb = FIRST input's res; unwired input = 8×8 black. Rust mirrors it as `node_resolutions(...)` in `render/mod.rs` (same rounding: `round`, same clamps — parity cases are the net).
- glExecutor: pool becomes size-keyed (`Map<"WxH", Target[]>` + per-size cursor); each pass renders at ITS node's resolution; `uRes` = node res; scale nodes render through the copy program into a target of the new size, with MIN/MAG set to NEAREST during the blit when `filter === "pixel"` (restored after). Thumb aspect per node = node res.
- Rust engine: same propagation; pool `HashMap<(u32,u32), Vec<PoolTex>>`; a cached second blit pipeline targeting `POOL_FORMAT` for scale passes; two cached samplers (linear shipped, nearest added) — scale's bind group picks by filter param.
- UI: Scale operator in the Add menu (Effects | Scale | Output sections); viewer frame uses the node's resolution aspect (thumbnails already per-node after this task); ParamsPanel renders scale via the generic param rows (factor scrub, width/height NumFields, filter Select) — a small `SCALE_SPEC` const, not a shaders/ manifest (scale has no frag).
- Preview cap stays 2048 on the JS side (applied inside `nodeResolutions` via `cap`); Rust cap 16384.

- [ ] **Step 1: Failing unit tests** — TS `nodeResolutions`: chain inherit, factor round, absolute override, cap clamp, unwired default; Rust `node_resolutions` mirror cases with identical numbers.
- [ ] **Step 2: FAIL. Step 3: Implement propagation + pools + scale pass in both engines.**
- [ ] **Step 4: Failing engine test (Rust)** — graph `source(8×8) → scale(factor 4, pixel) → output(64×92 fill)`: render succeeds, output still solid red (nearest upscale of solid color), and a `source → scale(0.25) → scale(4) → output` graph returns the right dimensions.

## Self-review notes

- T2 before T3 on purpose: the `render_chain`/place split lands before the resolution rework churns the same function.
- The undo capture-phase listener vs App's global undo is the riskiest UX seam in T1 — the RTL test asserting input-focus passthrough is the guard; a manual check that library-page undo still works after visiting Finish belongs in T1 Step 5.
- glExecutor's size-keyed pool must keep the RGBA16F ruling (JPEG intermediates) per size.
- Scale × preview cap interplay: factors are relative so a capped chain stays proportionally correct; the absolute width/height override is clamped by cap on the preview side only — WYSIWYG divergence is bounded by the same cap that already exists for sources (note in code).
- Filenames now embed output names: the path-safe scrub must apply to BOTH project and output names (shared helper in export.rs).
- Multi-output export re-encodes per output from ONE chain render — progress pct model needs a per-output segment split (extend, don't redesign).
