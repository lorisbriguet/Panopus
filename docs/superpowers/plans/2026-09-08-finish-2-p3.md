# Finish 2 — Phase 3 Implementation Plan (typography)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** D3 — the Text operator with Adobe-style direct manipulation on the preview, raster-cache parity, and (as the same drag system) preview-drag for Transform operators.

**Architecture:** The text node is a 1-input OVERLAY (per spec: content, font, size, fill, position, rotation; composites over its input). Rendering splits cleanly: a `shaders/text/text.frag` does the inverse-uv placement + over-composite of a RASTER texture (portable, parity-by-construction like transform); the only engine change is binding that raster per text node (`uTex1`). Rasterization is webview-only (canvas 2D + activated project fonts) and CACHED AS A FILE in app-data (`finish-rasters/`), referenced from the node (`rasterPath` + content-hash `rasterKey`) — never base64 in graph JSON (undo history must stay light). The Rust exporter loads the cached PNG; parity cases use committed synthetic rasters (parity never needs real font rasterization in Rust).

**Spec:** [docs/superpowers/specs/2026-09-08-finish-2-design.md](../specs/2026-09-08-finish-2-design.md) (D3)

## Global Constraints

- As P1/P2 (gates per commit, TS↔Rust lockstep, parity case per operator, shader portability triad: integer hashes, texel-snap sampling, polynomial trig).
- Graph JSON stays v1-additive: `kind: "text"`, params `{content, font, size, fill, x, y, rotate}`, node fields `rasterPath?: string`, `rasterKey?: string`.
- Raster files live in app-data `finish-rasters/<projectId>-<nodeId>.png` (one per node, overwritten on change; deleted lazily — orphan cleanup is out of scope).
- Stale-raster rule: engines render whatever raster they get; the WEBVIEW is responsible for re-rastering before export matters (export re-checks the key and re-rasters synchronously if stale — the one blocking wait allowed).

**Interfaces:**
- `text.frag`: uTex0 input, uTex1 raster; uniforms `uX uY` (page-fraction, −1..1), `uSize` (raster height as fraction of frame height, 0.01–1), `uRotate`, `uFill` (color, MULTIPLIES the raster rgb — white raster = pure fill color), `uOpacity` (0–1); inverse-transform sample of uTex1 (portable trig from halftone's psin/pcos — copy with provenance), `out = raster OVER input`.
- Raster aspect derives in-shader from `textureSize`? NO — GLSL/naga portability: pass `uRasterAspect` uniform... uniforms come from params only. Ruling: engines pass raster aspect as a RESERVED param injected at bind time is machinery; instead the frag samples uTex1 with uniform aspect handling via a `rasterAspect` PARAM the WEBVIEW writes onto the node when rastering (and parity cases set by hand). Cheap and honest.
- Rasterization does not exist yet in this task: tests/parity use committed rasters via the `rasterPath` parity-dir convention (same as sourcePath).

## Self-review notes

- The `rasterAspect`-as-param ruling avoids engine machinery but means a hand-edited graph can lie about aspect — rendering distorts, nothing breaks. Acceptable.
- Raster cap 1024px is the honest v1 limitation; print-size text will soften. P4's proof render will make this visible; revisit then (SDF or per-output raster heights).
- Text node undo: rasterPath/rasterKey ride the SAME commit as the param change that caused them, so undo restores param AND raster ref coherently (the FILE may be newer — engines just show the newer raster until re-raster; consistent-enough).
- Drag must not fight the ReactFlow canvas: preview drag only engages when the pointer starts INSIDE the block outline; the network layer sits above the preview (z-10) — the drag overlay must sit above the network (z-30) ONLY while a draggable node is selected, and pass through clicks outside the block.
